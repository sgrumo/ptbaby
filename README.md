# Averziano

Phoenix 1.8 + Ash 3 template repository with JSON API + LiveView, PostgreSQL, and production-ready patterns.

## Stack

- **Elixir** ~> 1.19, **Phoenix** ~> 1.8
- **Ash** ~> 3.33 with **AshPostgres** (data layer, migration generator) and **AshPhoenix** (LiveView forms)
- **Ecto** with PostgreSQL (binary UUIDs, UTC datetime timestamps)
- **Bandit** as HTTP server
- **esbuild** + **Tailwind CSS** for asset bundling (no Node.js)
- **Jason** for JSON encoding
- **Joken** for JWT verification
- **Corsica** for CORS

## Getting Started

### Prerequisites

- Elixir ~> 1.19
- PostgreSQL (or Docker)

### Setup

Start the database:

```bash
make up
```

Install dependencies, create the database, run migrations, and install assets:

```bash
mix setup
```

Start the server:

```bash
mix phx.server
```

Visit [`localhost:4000`](http://localhost:4000).

## Architecture

### Ash Domains

Business logic is modelled with [Ash](https://hexdocs.pm/ash) instead of hand-written Phoenix contexts. Each bounded context is an `Ash.Domain` (e.g. `Averziano.Accounts`) that declares its resources and a **code interface**:

```elixir
resources do
  resource Averziano.Accounts.User do
    define :register_user, action: :register
    define :get_user, action: :read, get_by: [:id]
  end
end
```

Resources (`Averziano.Accounts.User`) declare attributes, actions, identities and policies, and use `AshPostgres.DataLayer`. Strict separation between core (`lib/averziano/`) and web (`lib/averziano_web/`): the web layer only calls the domain code interface (`Accounts.register_user(params, actor: actor)`), never `Ash.*` on resources and never `Repo`.

Migrations are generated from resources: change a resource, run `mix ash.codegen add_something`, review the migration, commit it together with `priv/resource_snapshots/`. `mix ash.codegen --check` (run by `mix precommit` and CI) fails when resources drift from the migrations.

### Error Flow

Domain calls return Ash errors. `Averziano.Errors.normalize/1` maps them to typed error tuples:

```elixir
{:error, %Ash.Error.Forbidden{}}                      # -> {:error, :forbidden}
{:error, %Ash.Error.Invalid{errors: [%NotFound{}]}}   # -> {:error, :not_found}
{:error, %Ash.Error.Invalid{}}                        # -> {:error, :unprocessable_entity, %{email: ["has already been taken"]}}
```

The `FallbackController` accepts both raw Ash errors and typed tuples and maps them to HTTP status codes, so controllers use `action_fallback AverzianoWeb.FallbackController` and return whatever the domain returns.

### Authorization

Resources use `Ash.Policy.Authorizer`. The verified JWT claims are set as the Ash **actor** by `AverzianoWeb.Plugs.Auth` (`Ash.PlugHelpers.set_actor/2`) and by `AverzianoWeb.Live.AuthHook` (`socket.assigns.actor`); pass `actor:` to every domain call. The default policy is `authorize_if actor_present()`. Forbidden reads return an empty result set (`no_filter_static_forbidden_reads?: false`); forbidden writes return `Ash.Error.Forbidden`.

### Authentication

Token verification is swappable via config:

```elixir
# config/config.exs (production)
config :averziano, token_verifier: Averziano.Auth.Token

# config/test.exs
config :averziano, token_verifier: Averziano.Auth.TokenMock
```

The `AverzianoWeb.Plugs.Auth` plug reads the verifier from config at runtime, enabling mock injection in tests without Mox.

LiveView uses session-based auth via the `AverzianoWeb.Live.AuthHook` `on_mount` callback.

### Router Organization

| Layer | Pipeline | Description |
|---|---|---|
| `/health` | — | Health check (forwarded to `Health.Router`) |
| `/api` | `:api` | Public JSON endpoints |
| `/api` | `:api`, `:authenticated` | Protected JSON endpoints (`/api/users` example resource) |
| `/admin` | `:browser` | Admin LiveViews (`live_session` with auth hook) |

### Web Module Dispatch

`AverzianoWeb` provides quoted blocks via `use AverzianoWeb, :type`:

- `:controller` — JSON-only API controllers
- `:html_controller` — HTML + JSON controllers (admin, sessions)
- `:live_view` — LiveView modules
- `:live_component` — LiveView components
- `:html` — Phoenix HTML helpers

### OTP Supervision Tree

Flat `one_for_one` strategy:

```
Telemetry → Repo → [TelemetryUI] → DNSCluster → PubSub → Registry → DynamicSupervisor → Endpoint
```

`Registry` + `DynamicSupervisor` are included for per-session GenServer processes (real-time features).

## Development

### Common Commands

```bash
mix setup                    # Full project setup
mix phx.server               # Start dev server
iex -S mix phx.server        # Start with interactive shell
mix test                     # Run all tests
mix test path/to/test.exs    # Run a single test file
mix test path/to/test.exs:42 # Run test at specific line
mix test --failed            # Re-run failed tests
mix precommit                # Compile (warnings-as-errors) + format + codegen check + test
mix credo --strict           # Static analysis
mix dialyzer                 # Type checking (first run builds PLT)
mix ash.codegen name         # Generate migrations + snapshots from resource changes
mix ash.codegen --check      # Fail if resources have un-migrated changes
mix ash.migrate              # Run pending migrations
mix ash.reset                # Drop + recreate + migrate
mix ash.gen.domain Mod       # Scaffold a domain (Igniter)
mix ash.gen.resource Mod ... # Scaffold a resource (Igniter)
```

### Makefile

```bash
make up       # Start Docker Postgres
make down     # Stop Docker Postgres
make dev-api  # Start infra + setup + dev server
make test     # Start infra + run tests
```

### Precommit

Always run before committing:

```bash
mix precommit
```

This runs compilation with `--warnings-as-errors`, unlocks unused deps, formats code, checks that migrations are up to date with resources (`ash.codegen --check`), and runs the full test suite.

## Static Analysis

### Credo (strict mode)

Configured in `.credo.exs` with notable rules:

- `Readability.Specs` — every public function must have `@spec`
- `Refactor.ABCSize` max 40 — keeps functions small
- `MaxLineLength` 200
- `ModuleDoc` disabled
- `AliasUsage` — require aliases when nested > 1 and called > 2 times

### Dialyzer

Flags: `error_handling`, `unknown`, `unmatched_returns`, `underspecs`. PLT files cached in `priv/plts/` (gitignored).

## Testing

- **ExUnit** with **ExCoveralls** for coverage
- **Ash.Generator** for test data (`test/support/generator.ex`): `generate(user())`, `generate_many(user(), 3)`
- Generator auto-imported in both `DataCase` and `ConnCase`; `actor()` in `DataCase` returns the test actor
- Auth helpers in `ConnCase`: `authenticate(conn)`, `authenticate_superadmin(conn)`
- Test cases: `DataCase` (DB), `ConnCase` (HTTP), `ChannelCase` (WebSocket)
- Tests mirror source directory structure

## Observability

- **Health check:** `GET /health` via `plug_checkup` (checks database connectivity)
- **Metrics:** `telemetry_ui` for request counts/durations, DB query times, VM memory
- **Telemetry events:** Standard Phoenix + Ecto telemetry configured in `AverzianoWeb.Telemetry`
